# PYTHIA PS8.1 — отчёт о следующем шаге LZ77

## Реализация

- Сохранена модель `MODEL_LZ77 = 5` и версия модели 1. Изменена только внутренняя версия потока `PYLZ` с 1 на 2.
- В PS8.0 расстояние ссылки записывалось фиксированным `u16 LE` (2 байта). В PS8.1 оно кодируется каноническим ULEB128: 1 байт для 1–127, 2 байта для 128–16 383, 3 байта для 16 384–65 535.
- Декодер принимает обе версии `PYLZ`: v1/u16 LE и v2/ULEB128. Старые PS8.0 архивы с этим преобразованием остаются читаемыми.
- Декодер отклоняет нулевые, выходящие за окно, чрезмерно длинные и неканонические ULEB128 расстояния.
- Добавлены Rust unit tests: границы varint, отказ от overlong/noncanonical offset, чтение legacy v1, round-trip и некорректные потоки.
- Добавлен независимый Python wire-checker `benchmarks/check_lz77_v2.py`.
- Версия crate повышена до 0.8.1. Внешний контейнерный формат не менялся.

## Проверки, которые реально выполнены

Входной файл: `mixed_10mb_compression_test.bin`, 10 485 760 байт, SHA-256:
`999b1f32561deea75670f50d3cc7927565f78186b70e6f08602ae242b88a3c2f`.

Независимый C++ reference-прототип (не Rust implementation):

| Метрика | PS8.0 PYLZ v1 | PS8.1 PYLZ v2 |
|---|---:|---:|
| Token stream | 7 047 539 B | 6 962 476 B |
| Доля исходного размера | 67,21% | 66,40% |
| Encode | 8,71 MiB/s | 9,07 MiB/s |
| Decode | 449,10 MiB/s | 401,03 MiB/s |
| Round-trip | OK | OK |

Размер token stream снизился на 85 063 байта (1,21% относительно v1 token stream; 0,81% от размера исходного файла). Decode timing C++ reference в этом запуске стал ниже; единичный прогон не является стабильным сравнительным benchmark.

Независимый Python parser подтвердил:
- восстановление точного 10-MiB файла;
- совпадение SHA-256 исходного и восстановленного файла;
- чтение legacy PYLZ v1;
- границы ULEB128 1, 127, 128, 16 383, 16 384, 65 535;
- отклонение неканонического offset.

Внешние контрольные перекодировки:

| Вход | gzip -9 | bzip2 -9 |
|---|---:|---:|
| Исходный 10 MiB | 5 251 297 B | 4 719 626 B |
| PYLZ v2 token stream | 5 893 875 B | 5 543 253 B |

Следовательно, простой токенизатор LZ77 даже после компактного offset-кодирования пока не даёт выигрыша при последующем использовании этих внешних кодеков. Это не заменяет измерение штатного Rust `encode_best`/CME68.

## Не выполнено / ограничения

- `rustc`, `cargo`, `rustfmt` отсутствуют в окружении. Rust compilation, `cargo fmt --check`, `cargo test` и actual PYTHIA archive benchmark не запускались.
- C++ reference и Python checker проверяют wire-идею и не доказывают компилируемость Rust-кода.
- Нет доказательства улучшения конечного размера PYTHIA архива. Встроенный селектор обязан сравнивать полный размер дескриптора и entropy frame и оставлять baseline, если LZ77 не выигрывает.
- C++ encode/decode speed значения получены единичными прогонами, их нельзя считать устойчивой оценкой производительности.

## Следующий этап PS8.2

Нужен token-aware энтропийный слой, который не смешивает литералы, длины и расстояния в одном плоском byte stream: отдельно моделировать тип токена, длину match, длину literal-run и offset-классы; для литералов использовать контекст исходных байтов, а для offset — log-distance/context buckets. Сравнивать это с текущим CME68 на полном блоке с учётом всех заголовков и таблиц. До реальных Rust тестов и полных размеров не менять стабильную ветку.

## Дополнительные поисковые эксперименты (не включены в PS8.1)

На том же файле отдельно проверены два изменения жадного парсера в C++ reference-прототипах:

- **One-byte lazy matching:** отложить текущую ссылку, если совпадение со следующей позиции длиннее минимум на 2 байта. Token stream уменьшился до 6 943 755 B (ещё −18 721 B к PS8.1), но скорость кодирования упала примерно до 6,90 MiB/s против ~9,0 MiB/s у PS8.1. gzip/bzip2 результаты тоже улучшились лишь незначительно (5 882 432 / 5 526 752 B) и остались хуже исходного файла. В основной ветке не включено.
- **Cost-aware match selection:** выбирать ссылку по приблизительной выгоде `match_len - uleb_bytes(offset)`, а не только по максимальной длине. Token stream составил 6 957 435 B (−5 041 B к PS8.1), но единичный прогон был медленнее (~8,33 MiB/s). Выигрыш слишком мал, чтобы включать это без дополнительных наборов данных.

Эти варианты сохранены только как исследовательские измерения, а не как принятые изменения Rust-реализации.
