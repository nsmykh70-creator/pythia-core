# PYTHIA PS8.5 — статус разработки

## Изменения

- Добавлен выбор ограниченного бюджета hash-chain из профилей 32, 48 и 64.
- Для блоков размером от 4 KiB оценивается фактический размер PYLZ-токенов на первом префиксе до 64 KiB.
- Выбирается профиль с наименьшим размером пробного потока; при равенстве — профиль с меньшей глубиной.
- Полный блок кодируется только один раз после выбора профиля. Для блоков меньше 4 KiB используется профиль 32.
- Окно 65 535, min/max match 4/130, lazy parsing, PYLZ v2 и model ID 5 сохранены. Декодер и контейнерный формат не изменены.
- Пакетная версия: 0.8.5.

## Измерения C++ reference

Вход: `mixed_10mb_compression_test.bin`, 10 485 760 байт.

- Выбран профиль: 64.
- Размер PYLZ-потока: 6 786 714 байт.
- Доля от исходного размера: 0.647231.
- Скорость кодирования C++ reference (включая оценку профиля): 6.005 MiB/s в данном запуске.
- Декодирование и roundtrip: OK.
- SHA-256 токенного потока: `1e675f65dc11da095d747a4f9498114859a077f164bb8418f94591b2f7337b19`.

Показатель размера на этом входе совпадает с ранее измеренным depth-64 вариантом PS8.4 (6 786 714 байт) и на 56 697 байт меньше depth-48 результата PS8.4 (6 843 411 байт), то есть на 0.829% относительно depth-48. Это не доказывает общего выигрыша на иных данных.

### Синтетический корпус 1 MiB

| Набор | Выбранный профиль | PYLZ bytes | Roundtrip |
|---|---:|---:|---|
| random | 32 | 1 056 781 | OK |
| zeros | 32 | 16 152 | OK |
| periodic | 32 | 24 643 | OK |
| textlike | 32 | 16 212 | OK |
| structured | 32 | 16 143 | OK |

Профиль 32 выбран на всех пяти синтетических входах. Это показывает, что выбор глубины зависит от локального префикса, а не от типа файла; необходим более широкий корпус и оценка качества выборки.

## Ограничения и статус проверки

- Все приведённые измерения выполнены C++ reference harness, а не Rust-кодом.
- В среде отсутствуют `rustc` и `cargo`; Rust-компиляция, `cargo test` и rustfmt не выполнены.
- C++ reference выполняет roundtrip на каждом тестовом входе.
- Оценка выбирает профиль по размеру PYLZ-префикса, а не по окончательному размеру entropy frame. Поэтому это эвристика, а не глобальный оптимум полного PYAE-потока.
- На блоке 10 MiB пробный префикс добавляет до трёх коротких прогонов; фактическая цена измеряется в C++ reference и включена в указанное время кодирования.
- PS8.5 экспериментальная. Не заменять PS8.4 как стабильную без Rust-сборки, полных entropy-frame измерений и большего разнообразия данных.

## Следующие проверки

1. Собрать Rust на целевой системе и выполнить `cargo test`.
2. Сравнить размер полного PYAE frame для профилей 32/48/64, а не только PYLZ token stream.
3. Проверить выбор профиля на нескольких окнах каждого блока (начало/середина/конец), не нарушая строгого CPU-бюджета.
4. Проверить RAM-пик и скорость на 1 MiB, 10 MiB, 100 MiB и больших файлах.
